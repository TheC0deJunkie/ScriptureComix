## Directory Purposes

**components/:**
- Purpose: React functional components for UI features
- Contains: Modal dialogs, content panels, feature-specific UIs, loaders
- Key files: `ComicPanel.tsx` (core panel renderer), `MembershipModal.tsx` (tier gating UI)

**services/:**
- Purpose: Integration with external APIs and data management
- Contains: Gemini/Groq API calls, caching logic, scripture text loading
- Key files: `geminiService.ts` (main AI integration), `textLibrary.ts` (scripture loading)

**data/:**
- Purpose: Static application data
- Contains: Guided journey definitions with chapters, focus areas, XP rewards
- Key files: `guidedJourneys.ts` (learning paths)

**scripts/:**
- Purpose: Utility scripts for build and data processing
- Contains: Data import tools
- Key files: `importPublicDomainCanons.ts` (scripture dataset processing)

**public/:**
- Purpose: Static assets served directly
- Contains: Favicons, logos, and other public resources

**bible-translations-master/:**
- Purpose: Bundled Bible translation datasets
- Contains: Multiple translation directories (KJV, NIV, NLT, etc.) each with `*_bible.json`
- Generated by: `importPublicDomainCanons.ts` or cloned from external sources

**AL-QURAN_WITH_TRANSLATION_AND_TRANSLITERATION/:**
- Purpose: Quranic text with Arabic and transliteration
- Contains: Surah and verse structure in JSON format
- Status: Included as alternative scripture source

## Key File Locations

**Entry Points:**
- `index.html`: HTML shell, contains `<div id="root">` mount point
- `index.tsx`: React entry, ReactDOM.render() call
- `App.tsx`: Main component managing all state and orchestration

**Configuration:**
- `tsconfig.json`: TypeScript compiler options, module resolution
- `vite.config.ts`: Vite dev server (port 3000), build config, path alias `@`
- `package.json`: Dependencies (React 19, Lucide, Google GenAI), build scripts

**Core Logic:**
- `App.tsx` (1872 lines): All state management, event handlers, feature gating, effect hooks
- `types.ts`: Type definitions (`ComicPanelData`, `UserStats`, `BibleVersion`, `ArtStyle`, enums)
- `services/geminiService.ts`: Comic generation, panel image generation, quiz, speech
- `services/textLibrary.ts`: Scripture discovery, chapter text loading, catalog management
- `services/cacheService.ts`: localStorage wrapper, cache key generation, persistence

**Testing:**
- No test files present in codebase

**Data:**
- `data/guidedJourneys.ts`: Array of 4+ guided journeys with chapters and rewards

## Naming Conventions

**Files:**
- Components: PascalCase, `.tsx` extension (e.g., `ComicPanel.tsx`, `CharacterLibrary.tsx`)
- Services: camelCase, `.ts` extension (e.g., `geminiService.ts`, `textLibrary.ts`)
- Data: camelCase, `.ts` extension (e.g., `guidedJourneys.ts`)
- Scripts: camelCase, `.ts` extension (e.g., `importPublicDomainCanons.ts`)

**Directories:**
- lowercase, plural when containing multiple files (e.g., `components/`, `services/`, `data/`)
- PascalCase for book directory shortcuts (e.g., `KJV/`, `NIV/`)

**Variables/Constants:**
- camelCase for variables and functions: `selectedBook`, `setSelectedChapter()`
- UPPERCASE for module-level constants: `STORAGE_KEYS`, `TIER_LIMITS`, `FALLBACK_VERSION_PRIORITY`
- UPPERCASE for enums: `UserTier.FREE`, `ArtStyle.COMIC_MODERN`, `BibleVersion.NIV`

**Types:**
- PascalCase interfaces: `ComicPanelData`, `UserStats`, `ScriptureEntry`, `CachedChapter`
- PascalCase enums: `BibleVersion`, `ArtStyle`, `UserTier`

## Where to Add New Code

**New Feature (UI + Logic):**
- Primary code: Create component in `components/NewFeature.tsx`
- State hooks: Add useState/useEffect in `App.tsx`
- Service logic: Add function to `services/[relevant-service].ts` or create new service
- Types: Add interface to `types.ts`
- Storage: Add key to `STORAGE_KEYS` and useEffect persistence in `App.tsx`

**New Component/Modal:**
- Implementation: `components/ComponentName.tsx` (functional component with props)
- Integration: Import in `App.tsx`, wire state and callback handlers
- Style: Inline Tailwind classes (no external CSS files present)

**New Service Integration (External API):**
- Implementation: Create `services/newServiceName.ts`
- Environment config: Use `import.meta.env.VITE_*` for config
- Error handling: Throw at call time, not import time (for SSR compatibility)
- Fallback: Implement graceful fallback in `geminiService.ts` style (see Groq pattern)

**Utilities/Helpers:**
- Shared helpers: Add function to `services/[appropriate-service].ts` or create `services/utilityName.ts`
- Export from service file, import in `App.tsx` or components

**Data/Configuration:**
- Static data sets: Create file in `data/` directory (e.g., `data/journeys.ts`)
- Enums/constants: Add to `types.ts` (all type definitions centralized)
